# نظام إدارة شؤون الطلاب الذكي (STD)

منصة ويب لـ**عمادة شؤون الطلاب في جامعة بيشة**. يقدّم الطلاب من خلالها طلباتهم الرسمية ويتابعونها، ويطّلعون على الخدمات والأدلة والنماذج والأسئلة الشائعة، ويحصلون على إجابات فورية من مساعد ذكاء اصطناعي مبني على Google Gemini بتقنية التوليد المعزّز بالاسترجاع (RAG).

النظام مشروع تخرج من تخصص الذكاء الاصطناعي في كلية الحاسبات وتقنية المعلومات.

> الملفات الأخرى في هذا المجلد:
> - [ARCHITECTURE.md](ARCHITECTURE.md): بنية المجلدات، ومخطط قاعدة البيانات، ودورة حياة الطلب، ومسار الذكاء الاصطناعي (RAG)، ونموذج الأمان
> - [PAGES.md](PAGES.md): جميع الصفحات ونقاط الـ Backend مصنّفة حسب الدور

## 1. التقنيات المستخدمة

| الطبقة | التقنية | ملاحظات |
|---|---|---|
| لغة الخادم | **PHP 8+** | PHP خام بلا إطار عمل، ويستخدم مزايا PHP 8 مثل `match` والخصائص ذات الأنواع والدوال السهمية ودوال `mb_` |
| قاعدة البيانات | **MySQL / MariaDB** | قاعدة `std_system` بترميز `utf8mb4` ومحرك InnoDB مع مفاتيح أجنبية. ملف التصدير: `std_system.sql` |
| الوصول للبيانات | **PDO** | استعلامات مُجهّزة (Prepared Statements)، ووضع الأخطاء بالاستثناءات، و`FETCH_ASSOC`، مع تعطيل محاكاة التجهيز |
| خادم الويب | **Apache (XAMPP)** | التطبيق يعمل تحت المسار `/STD/`، والملف `includes/.htaccess` يمنع الوصول المباشر لملفات includes |
| إطار الواجهة | **Bootstrap 5.3.3 (نسخة RTL)** | يُحمَّل من jsDelivr CDN |
| الأيقونات | **Bootstrap Icons 1.11.3** | من CDN |
| الخطوط | **Google Fonts: Tajawal و Cairo** | خطوط عربية |
| برمجة الواجهة | **JavaScript خام** (`assets/js/main.js`) | واجهة الشات بوت (Fetch API)، والتنبيهات، والبحث في الجداول، والمعاينة، والحركات |
| التنسيق | CSS مخصص (`assets/css/style.css`) | اللون الأساسي `#1a5f7a`، ويُحدَّث الكاش تلقائياً عبر `filemtime` |
| توليد الإجابات | **Google Gemini API** (الافتراضي `gemini-2.5-flash`) | يُستدعى عبر cURL من `includes/gemini.php` |
| المتجهات (Embeddings) | **Gemini Embeddings** (`gemini-embedding-001` / `gemini-embedding-2-preview`) | تُخزَّن المتجهات بصيغة JSON داخل MySQL |
| البحث الدلالي | **تشابه جيب التمام (Cosine) في PHP** | الدالة `findRelevantChunks()` في `includes/functions.php` |
| الأمان | الجلسات، وتشفير bcrypt، ورموز CSRF، والهروب بـ `htmlspecialchars`، وحراسة الصفحات حسب الدور | انظر ARCHITECTURE.md القسم 6 |

الواجهة كلها عربية وباتجاه من اليمين لليسار (`<html lang="ar" dir="rtl">`).

## 2. أدوار المستخدمين

| الدور (`user_types.title`) | بالعربي | صفحة البداية | الملخص |
|---|---|---|---|
| `student` | طالب | `/student/dashboard.php` | يستخدم الخدمات والمساعد الذكي والطلبات والملف الشخصي |
| `admin` | إداري | `/admin/dashboard.php` | يعالج الطلبات، ويدير المحتوى وقاعدة المعرفة، ويراجع محادثات الشات بوت |
| `manager` | مدير | `/manager/dashboard.php` | كل صلاحيات الإداري، ومعها المستخدمون والبنية الأكاديمية والتقارير وإعدادات النظام |
| `academic_advisor` | مرشد أكاديمي | `/advisor/dashboard.php` | يعالج الطلبات الموجّهة إليه من طلابه، ويطّلع على قائمة طلابه، ويعمل على محاضر الاجتماعات |

الدالة `isAdmin()` تُرجع true لـ`admin` و`manager` **كليهما**، لذا يجتاز المدير كل فحوصات الإداري.

## 3. المميزات

### 3.1 الموقع العام
- **الصفحة الرئيسية** (`index.php`): قسم ترحيبي، وشريط إحصائيات، والمميزات، ونبذة عن الجامعة والعمادة، وفريق العمل، ودعوة للتسجيل، وتذييل.
- **صفحة عن النظام** (`about.php`): تعريف بالنظام والجامعة، ومهام العمادة، وستة أهداف للمشروع، والتقنيات المستخدمة، وفريق التطوير.
- **إنشاء حساب** (`signup.php`): تسجيل ذاتي للطلاب. الكلية والدرجة والتخصص والمرشد قوائم متتابعة تعمل بـ JavaScript. يتحقق النموذج من صيغة البريد، ومن عدم تكرار البريد أو رقم الهوية، ومن أن كلمة المرور 8 أحرف على الأقل وتطابق التأكيد.
- **تسجيل الدخول** (`login.php`): وضعان. الطالب يدخل بالبريد **أو** الرقم الجامعي، والموظفون (إداري، مدير، مرشد) يدخلون بالبريد. بعد الدخول يُوجَّه كل مستخدم حسب دوره.

### 3.2 المساعد الذكي (RAG)
- واجهة محادثة للطالب تحفظ سجل المحادثات (آخر 10)، مع مؤشر كتابة، وتعرض صيغة Markdown من نص عريض ونقاط وروابط تحميل.
- **التوليد المعزّز بالاسترجاع**: يُحوَّل السؤال إلى متجه، ويُقارَن مع كل المقاطع بتشابه جيب التمام، ثم تُرسَل أفضل *N* مقاطع (الإعداد `max_chunks_retrieve`، والافتراضي 5) إلى Gemini مع تعليمات نظام بالعربية.
- **عدة طبقات احتياطية**:
  1. لا يوجد مفتاح API: بحث نصي في الأسئلة الشائعة ثم في الخدمات.
  2. فشل إنشاء المتجه: بحث `LIKE` في نصوص المقاطع.
  3. لم تُعثر على مقاطع: بحث `LIKE` في أسئلة الأسئلة الشائعة وكلماتها المفتاحية.
  4. أي استثناء: بحث نصي احتياطي، ويُسجَّل السؤال كسؤال غير مُجاب.
- **اكتشاف الثقة المنخفضة**: إذا قلّ أعلى تشابه عن **0.55**، أو احتوت الإجابة عبارات مثل "لا توجد معلومات"، يقترح البوت تقديم طلب رسمي.
- **دورة الأسئلة غير المُجابة**: تُحفظ الأسئلة منخفضة الثقة في `unknown_questions` (مع منع التكرار خلال 5 دقائق)، ويُرسَل إشعار لكل إداري ومدير نشط. من صفحة الأسئلة غير المُجابة يمكن تحويل السؤال إلى مدخل في قاعدة المعرفة، فتصبح حالته `added_to_kb`.
- **روابط تحميل داخل الإجابات**: الأدلة والنماذج تضيف روابط ملفاتها إلى قاعدة المعرفة، فيستطيع البوت الرد برابط تحميل مباشر.
- **إمكانية تفعيل الشات بوت أو إيقافه** من الإعدادات (`chatbot_enabled`).

### 3.3 قاعدة المعرفة
- إضافة وتعديل وحذف مدخلات من الأنواع: خدمة، سؤال شائع، دليل، نموذج، سياسة، معلومة. لكل مدخل حالة: منشور أو مسودة أو مؤرشف.
- يُقسَّم المحتوى إلى مقاطع (الإعداد `chunk_size`، والافتراضي 500 حرف) ولكل مقطع متجه.
- **مزامنة تلقائية**: حفظ خدمة أو سؤال شائع أو دليل أو نموذج يُنشئ مدخله في قاعدة المعرفة أو يحدّثه.
- **توليد المتجهات على دفعات** (`generate_embeddings.php`): حتى 50 مقطعاً في كل تشغيل، مع تأخير 200 مللي ثانية بين الطلبات لاحترام حدود الاستخدام. يظهر التقدّم في صفحة الإعدادات ولوحة الإداري.

### 3.4 الطلبات (التذاكر)
- يختار الطالب خدمة ثم يقدّم طلباً فيه عنوان ووصف وأولوية ومرفق اختياري (pdf أو doc أو docx أو jpg أو jpeg أو png، بحد أقصى 5 ميغابايت).
- **التوجيه الذكي** حسب الحقل `assigned_role` في الخدمة:
  - `admin`: يصل إشعار لجميع الإداريين والمديرين.
  - `advisor`: يُسنَد الطلب لمرشد الطالب الأكاديمي ويصله إشعار.
  - `both`: يُسنَد للمرشد، ويصل إشعار للإداريين أيضاً.
- **الحالات**: جديد ← تحت المراجعة ← تم الرد ← مكتمل / مرفوض / مغلق.
- **الأولويات**: منخفضة، متوسطة، عالية.
- **ردود متسلسلة** مع مرفقات. رد الموظف يحوّل الحالة تلقائياً إلى "تم الرد".
- يستطيع الموظفون تغيير الحالة والأولوية والمُسنَد إليه. المرشد لا يتعامل إلا مع الطلبات المُسندة إليه.
- يصل الطالب إشعار عند كل تغيير في الحالة وعند كل رد.

### 3.5 محاضر الاجتماعات والتوصيات
- يمكن للإداريين والمديرين والمرشدين فتح وحدة **اجتماعات لجان العمادة**. لكل اجتماع عنوان وتاريخ وملاحظات.
- لكل اجتماع **توصيات**، وفي كل توصية:
  - القرار: موافقة، أو رفض، أو أخرى، أو ملاحظات (وإذا كان فارغاً فالتوصية في الانتظار)
  - نوع الدعم: سلفة، أو جائزة، أو إعانة مقطوعة، أو إعانة زواج، أو أخرى
  - مبلغ الدعم بالريال
  - حالة الصرف: تم الصرف أو لم يتم الصرف
- **تُحسب حالة الاجتماع تلقائياً**، فيصبح "مكتمل" إذا كانت فيه توصية واحدة على الأقل ولم تبقَ أي توصية في الانتظار.
- تعرض صفحة الاجتماع شريط تقدّم وعدد التوصيات في كل حالة.
- في الواجهة، الإداريون والمديرون فقط يُنشئون الاجتماعات ويعدّلونها ويحذفونها ويحذفون التوصيات. المرشد يطّلع على الاجتماعات ويضيف التوصيات ويعدّلها. ملاحظة: الملف `backend/save_meeting.php` نفسه يقبل المرشدين أيضاً، فهذا القيد مطبّق في الواجهة فقط.

### 3.6 إدارة المحتوى
- **الخدمات**: العنوان، والوصف، والقسم، والشروط، والمستندات المطلوبة، والخطوات، والكلمات المفتاحية، والأيقونة، والحالة، وجهة التوجيه.
- **الأدلة** و**النماذج**: ملفات قابلة للتحميل مع وصف، وترتبط بخدمة أو قسم.
- **الأسئلة الشائعة**: السؤال، والإجابة، والكلمات المفتاحية، والترتيب، والربط بخدمة أو قسم.
- يتصفح الطالب الخدمات (مع تصفية حسب القسم وبحث)، والأدلة والنماذج (تبويبان مع بحث)، والأسئلة الشائعة.

### 3.7 إدارة المستخدمين والبنية الأكاديمية (المدير)
- الطلاب: بحث، وتصفية حسب الكلية أو الحالة، وإضافة، وتعديل، وتغيير الحالة، وتعيين المرشد، وحذف.
- الإداريون والمرشدون الأكاديميون: إضافة وتعديل وحذف.
- تفعيل المستخدمين أو إيقافهم (`toggle_user_status.php`). المستخدم الموقوف يُسجَّل خروجه عند تحميل الصفحة التالية، لأن `requireLogin()` تتحقق من حالته في كل طلب.
- الكليات، والدرجات العلمية، والتخصصات (كل تخصص مرتبط بكلية ودرجة)، والأقسام، وأنواع المستخدمين.

### 3.8 الإشعارات وسجل النشاط
- إشعارات داخل النظام مع عدّاد على أيقونة الجرس، وقائمة منسدلة بآخر 5 إشعارات، وروابط مباشرة، وخيار "تحديد الكل كمقروء".
- يسجّل جدول `activity_logs` الإجراءات المهمة (الدخول، وتقديم الطلبات، والردود، وحفظ المحتوى، والحذف، وتغيير الإعدادات) مع عنوان IP.

### 3.9 التقارير (المدير)
- بطاقات ملخّصة: الطلاب، والطلبات، والمحادثات، وسجلات المعرفة.
- الطلبات حسب الحالة، والطلبات حسب الخدمة (أعلى 10)، والطلبات الشهرية لآخر 6 أشهر.
- إحصائيات الشات بوت: المحادثات، والرسائل، وأسئلة الطلاب، ومتوسط الرسائل لكل محادثة.
- نشاط المستخدمين اليومي لآخر 14 يوماً، والمستخدمون حسب الدور.
- الرسوم البيانية مبنية بأشرطة التقدّم في Bootstrap، ولا تُستخدم مكتبة رسوم.

### 3.10 إعدادات النظام (المدير)
- اسم الموقع بالعربي والإنجليزي، واسم الجامعة، وبريد الدعم ورقمه، ووضع الصيانة.
- رفع الشعار وحذفه (png أو jpg أو jpeg أو svg أو webp)، ويظهر الشعار في شريط التنقل.
- إعدادات الذكاء الاصطناعي: مفتاح Gemini API، ونموذج المحادثة (`gemini-2.5-flash` أو `2.5-pro` أو `2.5-flash-lite` أو `2.0-flash`)، ونموذج المتجهات، وتفعيل الشات بوت، وحجم المقطع، وعدد المقاطع المسترجعة.
- حالة توليد المتجهات، مع زر لتوليد المتبقي.

### 3.11 الملف الشخصي
- لكل دور صفحة ملف شخصي لتعديل البيانات، ورفع صورة شخصية، وتغيير كلمة المرور. للطالب حقول أكاديمية إضافية.
- الصورة الافتراضية تختلف حسب الجنس (`avatar-male.svg` / `avatar-female.svg`).

## 4. التثبيت (محلياً على XAMPP)

1. انسخ المشروع إلى `C:\xampp\htdocs\STD`. يجب أن يكون اسم المجلد `STD` **بالضبط**، لأن المسارات مثل `/STD/...` مكتوبة مباشرة في الكود.
2. شغّل **Apache** و**MySQL** من لوحة تحكم XAMPP.
3. أنشئ في phpMyAdmin قاعدة بيانات باسم `std_system` بترميز `utf8mb4_general_ci`، ثم استورد الملف `std_system.sql`.
4. إذا كانت بيانات الدخول مختلفة عن إعدادات XAMPP الافتراضية (`root` بلا كلمة مرور)، عدّل الملف `includes/db.php`.
5. تأكد من تفعيل امتدادات PHP التالية: `curl` و`pdo_mysql` و`mbstring`.
6. افتح `http://localhost/STD/`.
7. سجّل الدخول كمدير، وادخل **الإعدادات**، وضع مفتاح Gemini API **الخاص بك** من [Google AI Studio](https://aistudio.google.com/apikey)، ثم ولّد المتجهات من صفحة قاعدة المعرفة أو صفحة الإعدادات.

### سكربتات الترحيل (`backend/migrate*.php`)
سكربتات تُشغَّل مرة واحدة لترقية قواعد البيانات القديمة: تضيف الكليات والدرجات والتخصصات، وتحوّل المرشدين إلى مستخدمين، وتضيف جداول الاجتماعات وتوجيه الطلبات والأسئلة غير المُجابة. **الاستيراد الجديد للملف `std_system.sql` يتضمن كل هذه التغييرات.**

### التشخيص
الصفحة `backend/test_gemini.php` (للمدير فقط) تعرض نماذج Gemini المتاحة وتختبر نقاط المحادثة والمتجهات بالمفتاح المضبوط.
